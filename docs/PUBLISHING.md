# Публикация обновлений БАЗИС

В публичном репозитории настроен отдельный безопасный сценарий публикации обновлений продукта.

## Как опубликовать обновление

1. Откройте вкладку **Actions**.
2. Выберите workflow **Publish public update**.
3. Нажмите **Run workflow**.
4. Заполните:
   - название обновления;
   - категорию;
   - краткое описание;
   - подробности;
   - для кого предназначено изменение;
   - ссылку на продукт, если нужна.
5. Нажмите **Run workflow**.

GitHub автоматически:

- создаст отдельную страницу в папке `updates/`;
- добавит обновление в публичный индекс;
- добавит запись в `CHANGELOG.md`;
- сделает commit в публичный репозиторий.

## Для автоматизации из других процессов

Workflow также принимает событие `repository_dispatch` типа `publish_update`.

Пример payload:

```json
{
  "event_type": "publish_update",
  "client_payload": {
    "title": "Единая карточка объекта",
    "category": "Новая функция",
    "summary": "Все ключевые данные по объекту теперь собраны в одном месте.",
    "details": "Добавили единое представление объекта, план–факт и проблемные точки.",
    "audience": "Строительные и монтажные компании",
    "product_link": "https://calcul369.ru"
  }
}
```

Это позволяет позже подключить закрытый процесс разработки, ZedCode или другой оркестратор, не публикуя исходный код.

## Безопасность

Автоматизация публикует только текст, который передан ей явно. Она не читает приватные репозитории и не копирует исходный код.

Перед публикацией выполняется базовая проверка на похожие на секреты строки. Если обнаружен токен или ключ, публикация останавливается.
