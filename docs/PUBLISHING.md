# Публикация обновлений БАЗИС

В публичном репозитории настроен безопасный сценарий публикации обновлений продукта и автоматической подготовки контента для рекламных каналов.

## Что происходит после запуска

GitHub автоматически:

- создаёт публичную страницу обновления в `updates/`;
- добавляет запись в `CHANGELOG.md`;
- создаёт готовую статью для Дзена в `distribution/dzen/`;
- создаёт готовый короткий пост для MAX в `distribution/max/`;
- записывает оба материала в `distribution/manifest.json` со статусом `draft`.

**Важно:** статус `draft` означает, что материалы только подготовлены. Сам этот публичный workflow не отправляет их в Дзен или MAX и поэтому не может случайно опубликовать материал вне расписания.

## Как опубликовать обновление вручную

1. Откройте вкладку **Actions**.
2. Выберите workflow **Publish public update**.
3. Нажмите **Run workflow**.
4. Заполните название, категорию, краткое описание, подробности, аудиторию и ссылку.
5. Нажмите **Run workflow**.

## Автоматизация из закрытого Kalkulytor

Закрытый репозиторий `Lenar369/Kalkulytor` уже передаёт безопасное описание через событие `repository_dispatch` типа `publish_update`.

Передаётся только подготовленный текст:

```json
{
  "event_type": "publish_update",
  "client_payload": {
    "title": "Единая карточка объекта",
    "category": "Новая функция",
    "summary": "Все ключевые данные по объекту теперь собраны в одном месте.",
    "details": "Добавили единое представление объекта, план–факт и проблемные точки.",
    "audience": "Строительные и монтажные компании",
    "product_link": "https://calcul369.ru"
  }
}
```

## Правила контента

- CTA для CRM ведёт только на `https://calcul369.ru`.
- Телефон и `tel:` в публикационные тексты не добавляются.
- Исходный код, серверная конфигурация и клиентские данные не копируются.
- Перед генерацией выполняется базовая проверка на строки, похожие на токены и секреты.
- Повторная публикация в каналы должна ориентироваться на `manifest.json` и статусы каналов, чтобы исключить дубли.
